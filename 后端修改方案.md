# 请假审核功能后端修改方案

## 一、数据库表结构修改

### 1. 增加审核状态字段

```sql
ALTER TABLE student_leave 
ADD COLUMN teacher_state INT DEFAULT 0 COMMENT '教师审核状态: 0=未审核, 2=通过, 3=不通过',
ADD COLUMN admin_state INT DEFAULT 0 COMMENT '管理员审核状态: 0=未审核, 2=通过, 3=不通过';
```

### 2. 数据迁移（如果已有数据）

```sql
-- 将现有的 state 字段值迁移到新字段
UPDATE student_leave 
SET teacher_state = CASE 
    WHEN state = 2 THEN 2 
    WHEN state = 3 THEN 3 
    ELSE 0 
END,
admin_state = 0;
```

## 二、实体类修改

### StudentLeave.java

```java
public class StudentLeave {
    private Integer studentLeaveId;
    private Integer studentId;
    private String studentNum;
    private String studentName;
    private Integer teacherId;
    private String teacherName;
    private String leaveDate;
    private String reason;
    
    // 新增字段
    private Integer teacherState;  // 教师审核状态
    private Integer adminState;    // 管理员审核状态
    
    // 保留原有字段（用于前端展示最终状态）
    private Integer state;         // 最终状态（计算得出）
    private String stateName;      // 状态名称
    
    private String teacherComment;
    private String adminComment;
    
    // getter 和 setter 方法...
    
    /**
     * 计算最终审核状态
     * 规则：
     * - 只要有一方通过(2)，就显示为通过(2)
     * - 只有一方不通过(3)且另一方未审核(0)，显示为不通过(3)
     * - 两方都未审核(0)，显示为待审核(1)
     */
    public Integer calculateFinalState() {
        // 如果任一方通过，则最终状态为通过
        if (teacherState != null && teacherState == 2) {
            return 2;
        }
        if (adminState != null && adminState == 2) {
            return 2;
        }
        
        // 如果任一方不通过，则最终状态为不通过
        if (teacherState != null && teacherState == 3) {
            return 3;
        }
        if (adminState != null && adminState == 3) {
            return 3;
        }
        
        // 默认待审核
        return 1;
    }
}
```

## 三、Service 层修改

### StudentLeaveService.java

```java
@Service
public class StudentLeaveService {
    
    @Autowired
    private StudentLeaveMapper studentLeaveMapper;
    
    /**
     * 审核请假申请
     * @param studentLeaveId 请假ID
     * @param comment 审核意见
     * @param state 审核状态 (2=通过, 3=不通过)
     * @param userType 审核人类型 ("teacher" 或 "admin")
     */
    public void checkLeave(Integer studentLeaveId, String comment, Integer state, String userType) {
        StudentLeave leave = studentLeaveMapper.selectById(studentLeaveId);
        if (leave == null) {
            throw new RuntimeException("请假记录不存在");
        }
        
        if ("teacher".equals(userType)) {
            // 教师审核
            leave.setTeacherState(state);
            leave.setTeacherComment(comment);
        } else if ("admin".equals(userType)) {
            // 管理员审核
            leave.setAdminState(state);
            leave.setAdminComment(comment);
        } else {
            throw new RuntimeException("无效的审核人类型");
        }
        
        // 计算最终状态
        Integer finalState = leave.calculateFinalState();
        leave.setState(finalState);
        
        // 更新数据库
        studentLeaveMapper.updateById(leave);
    }
    
    /**
     * 获取请假列表
     */
    public List<StudentLeave> getLeaveList(Integer state, String search) {
        List<StudentLeave> list = studentLeaveMapper.selectList(state, search);
        
        // 为每条记录计算最终状态
        for (StudentLeave leave : list) {
            Integer finalState = leave.calculateFinalState();
            leave.setState(finalState);
            
            // 设置状态名称
            leave.setStateName(getStateName(finalState));
        }
        
        return list;
    }
    
    /**
     * 获取状态名称
     */
    private String getStateName(Integer state) {
        if (state == null) {
            return "未知";
        }
        switch (state) {
            case 1: return "待审核";
            case 2: return "已通过";
            case 3: return "不通过";
            default: return "未知";
        }
    }
}
```

## 四、Controller 层修改

### StudentLeaveController.java

```java
@RestController
@RequestMapping("/api/studentLeave")
public class StudentLeaveController {
    
    @Autowired
    private StudentLeaveService studentLeaveService;
    
    /**
     * 审核请假
     * POST /api/studentLeave/studentLeaveCheck
     * 
     * 请求参数：
     * {
     *   "studentLeaveId": 7,
     *   "teacherComment": "同意",  // 或 adminComment
     *   "state": 2,                 // 2=通过, 3=不通过
     *   "userType": "teacher"       // "teacher" 或 "admin"
     * }
     */
    @PostMapping("/studentLeaveCheck")
    public DataResponse checkLeave(@RequestBody Map<String, Object> params) {
        try {
            Integer studentLeaveId = (Integer) params.get("studentLeaveId");
            String comment = (String) params.get("teacherComment");
            if (comment == null) {
                comment = (String) params.get("adminComment");
            }
            Integer state = (Integer) params.get("state");
            String userType = (String) params.get("userType");
            
            // 如果没有传 userType，根据当前登录用户判断
            if (userType == null || userType.isEmpty()) {
                userType = getCurrentUserType(); // 从session或token中获取
            }
            
            studentLeaveService.checkLeave(studentLeaveId, comment, state, userType);
            
            return new DataResponse(0, null, "审核成功");
        } catch (Exception e) {
            return new DataResponse(-1, null, "审核失败: " + e.getMessage());
        }
    }
    
    /**
     * 获取请假列表
     * GET /api/studentLeave/getStudentLeaveList?state=2&search=xxx
     */
    @GetMapping("/getStudentLeaveList")
    public DataResponse getLeaveList(
            @RequestParam(required = false) Integer state,
            @RequestParam(required = false) String search) {
        try {
            List<StudentLeave> list = studentLeaveService.getLeaveList(state, search);
            return new DataResponse(0, list, null);
        } catch (Exception e) {
            return new DataResponse(-1, null, "查询失败: " + e.getMessage());
        }
    }
    
    /**
     * 获取当前用户类型
     */

        // 从 session、token 或 security context 中获取

        //     return "admin";
        // }
        // return "teacher";
        return "teacher"; // 临时实现
    }
}
```

## 七、审核状态流转示例

| 场景 | teacher_state | admin_state | 最终 state | 说明 |
|------|--------------|-------------|-----------|------|
| 初始状态 | 0 | 0 | 1 | 待审核 |
| 教师通过 | 2 | 0 | 2 | 已通过（教师） |
| 教师通过后，管理员也通过 | 2 | 2 | 2 | 已通过 |
| 教师通过后，管理员不通过 | 2 | 3 | 2 | **仍为通过**（按新规则） |
| 教师不通过 | 3 | 0 | 3 | 不通过 |
| 教师不通过，管理员通过 | 3 | 2 | 2 | **变为通过**（管理员覆盖了） |
| 仅管理员通过 | 0 | 2 | 2 | 已通过（管理员） |

## 八、注意事项

1. **权限控制**：确保教师只能修改 `teacher_state`，管理员只能修改 `admin_state`
2. **审核意见**：教师和 administrator 的意见分别存储在 `teacherComment` 和 `adminComment`
3. **日志记录**：建议增加审核日志表，记录每次审核的时间、操作人、审核结果
4. **通知机制**：当一方审核后，可以通知另一方进行审核

## 九、可选优化

如果需要更严格的审核流程（双方都必须通过才算通过），只需修改 `calculateFinalState()` 方法：

```java
public Integer calculateFinalState() {
    // 严格模式：双方都必须通过
    if (teacherState != null && teacherState == 3) {
        return 3; // 教师不通过
    }
    if (adminState != null && adminState == 3) {
        return 3; // 管理员不通过
    }
    if ((teacherState != null && teacherState == 2) && 
        (adminState != null && adminState == 2)) {
        return 2; // 双方都通过
    }
    return 1; // 待审核
}
```
